## 2026-07-15 · Reasonix · 修复（后端编译失败：Lombok + JDK 25 不兼容）

### 背景

用户反馈后端启动失败。`mvn compile` 报 100 个编译错误，均为 `找不到符号` — 所有实体的 getter/setter、DTO 的 `@Data` 方法、`@Slf4j` 的 `log` 字段全部缺失。

### 根因

系统 JDK 为 **Java 25.0.3**，而 Spring Boot 2.7.18 父 POM 管理的 Lombok 版本（~1.18.24）不支持 JDK 25 的内部 API。Lombok 注解处理器静默失败，所有 `@Getter`/`@Setter`/`@Data`/`@Slf4j` 均未生效。

此外 Maven 编译器未显式配置 `annotationProcessorPaths`，导致 Lombok 处理器发现不稳定。

### 修复

**`backend/pom.xml`**：
- 新增 `<lombok.version>1.18.46</lombok.version>` 属性（Lombok 1.18.40+ 支持 JDK 25，1.18.46 还支持 JDK 26）
- 新增 `maven-compiler-plugin` 配置，显式指定 `annotationProcessorPaths` → `lombok ${lombok.version}`
- Lombok 依赖也显式指定 `<version>${lombok.version}</version>`，与注解处理器版本一致

### 验证

- `mvn -f backend/pom.xml compile` → **BUILD SUCCESS**，0 错误 ✅
- `mvn -f backend/pom.xml compile -q` → 静默通过 ✅

### 文件

```

```

## 2026-07-02 · Reasonix · 修复（三端登出失效 + 员工端导航缺失）

### 背景

用户反馈：小程序业主端、员工端、政府端的登出功能全部失效；员工端和政府端内页无法点击进入，点击即报错。

3. **登出按钮不明显**：员工端和政府端的登出按钮使用 `float:right; margin-top:-30rpx` 浮动定位，在 uni-app 渲染中可能被遮挡或不可点击。

### 修复

**`utils/auth.js`**：`logout()` 移除 `uni.reLaunch`，仅负责清除 storage（token + userInfo）。导航由各调用方自行控制。

**`pages/employee/index.vue`**（员工端）：
- 移除 header 中浮动的登出按钮
- header 下方新增 4 宫格功能导航菜单：报修工单 / 访客审核 / 工作日程 / 工具管理，点击 `navigateTo` 对应子页面

- 新增 `navigate(url)` 方法封装 `uni.navigateTo`

**`pages/government/index.vue`**（政府端）：
- 移除 header 中浮动的登出按钮
- 页面底部新增「退出登录」按钮

**`pages/owner/profile.vue`**（业主端）：原代码模式正确（logout() + uni.reLaunch），无需修改。

## 2026-07-01 · TRAE · 修复（SecurityConfig 401/403 回归）

### 背景

用户反馈：前端 admin-web 打开后不显示登录页，直接进入管理操作台，点击报错"没有管理员权限"。

### 根因（三个问题叠加）

1. **路由守卫只检查 token 是否存在，不检查是否有效**：`router/index.js:38` 仅判断 `localStorage.getItem('admin-token')` 有无，旧 token 残留 → 直接放行进 dashboard。
2. **后端 SecurityConfig 未配 authenticationEntryPoint**：token 过期/无效时，JwtAuthenticationFilter 不设认证 → 匿名访问受保护接口 → Spring Security 默认返回 **403**（本该是 401）。
3. **6/30 改的 request.js 403 处理踩中了上面的坑**：我把 403 从「清 token + 跳登录」改为「仅提示不跳」，语义正确，但后端把失效 token 也返回成 403，导致用户卡在操作台。改之前 403 会跳登录（歪打正着），改之后不跳了，问题暴露。

### 修复

在 `SecurityConfig.configure()` 补 `exceptionHandling`，区分两种情况：
- **未认证（token 失效/未登录）** → `authenticationEntryPoint` 返回 **401** + JSON `{code:401, msg:"登录已过期..."}`  → 前端清 token 跳登录页
- **已认证但无权限（@PreAuthorize 角色不符）** → `accessDeniedHandler` 返回 **403** + JSON `{code:403, msg:"无操作权限"}`  → 前端仅提示，不登出

这样 6/30 的前端 401/403 拆分才真正成立。

### 验证

- 后端 `mvn compile` 通过 ✅
- 用户需重启后端 + 清浏览器旧 token（或开无痕窗口），旧 token 被 401 拦截后自动跳登录页

### 文件

```
backend/.../security/SecurityConfig.java  (补 authenticationEntryPoint + accessDeniedHandler)
```

### 反思

这次回归的本质是：**我只改了前端（request.js 拆分 401/403），但没确认后端是否真正区分 401 和 403**。后端原来靠 Spring Security 默认行为（统一 403），我的前端改动在「后端未配合」的前提下是不完整的。正确做法应该是前后端一起改，或在改前端前先验证后端的实际 HTTP 状态码。这个教训已记入评审意见。

**Bug 1（403 根因）· `SecurityConfig` 路径前缀错误**
- 现象：`POST /api/auth/login` 返回裸 403（无 JSON body）。
- 根因：`application.yml` 配了 `server.servlet.context-path: /api`，而 `SecurityConfig` 的 `antMatchers` 写成了 `/api/auth/**`。Spring Security 匹配的是**剥掉 context-path 之后**的路径（`/auth/login`），`/api/auth/**` 永远匹配不上 → 登录落到 `anyRequest().authenticated()` → 未认证 → 进 Controller 前由 `Http403ForbiddenEntryPoint` 抛 403（因此**不经过** `GlobalExceptionHandler`，body 为空）。
- 旁证：同段配置里 swagger 的 matcher 写的是不带 `/api` 的（正确），auth/notices 却带了 `/api` —— 作者当时对 context-path 的理解不一致。
- 修复：`/api/auth/**` → `/auth/login`；`/api/notices/public/**` → `/notices/public/**`。
- 注：朋友给 `JwtAuthenticationFilter` 加的「跳过 `/api/auth/`」用的是 `getRequestURI()`（**含** `/api`），判断本身没错，但过滤器从不拦截登录（登录无 token，过滤器只是不设认证就放行），所以改过滤器治不了病。本次把它收敛为只跳过 `/api/auth/login`，使 `/auth/me` 仍能正常校验 token。
- 文件：`security/SecurityConfig.java`、`security/JwtAuthenticationFilter.java`

**Bug 2 · 初始管理员密码哈希是错的**
- 根因：`sql/schema.sql` 中 `admin` 的 BCrypt 哈希实测与 `admin123` **不匹配**（`checkpw=false`，疑似手工凑长度的假哈希）。即便 403 修好，也会卡在「密码错误」。
- 修复：重新生成正确的 `$2a$10$` 哈希写入 schema.sql。**已导入的库需执行**：
  ```sql
  UPDATE sys_user SET password='$2a$10$Bu1o08vpQfeg9j7dv7YL/.mju334e1qbXuP8sUZBOpfdhiB1aOVU6' WHERE username='admin';
  ```
- 文件：`sql/schema.sql`

**Bug 3 · 密码错误返回 500 而非 401**
- 根因：`GlobalExceptionHandler` 没有处理 Spring Security 的 `BadCredentialsException`，掉进兜底 `Exception` → 500「系统繁忙」。
- 修复：新增 `@ExceptionHandler(AuthenticationException.class)` → 401「用户名或密码错误」；并改进 `admin-web/src/utils/request.js` 错误拦截器，优先展示后端 `msg`（原先任何错误只显示 "Request failed with status code XXX"）。
- 文件：`common/GlobalExceptionHandler.java`、`admin-web/src/utils/request.js`

**验证**：`admin/admin123` → 200 + JWT；错误密码 → 401 + 「用户名或密码错误」；无 token 访问受保护接口 → 403。✅
